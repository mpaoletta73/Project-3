Write-Up

Motivation

Our main question is how Pacific sea surface temperatures shift during El Niño events. Instead of only looking at the Niño 3.4 number, we wanted to see where the warming or cooling shows up along a west-to-east slice of the equatorial Pacific. When Niño 3.4 is warmer or cooler than usual, is the rest of the sampled Pacific doing the same thing, or is the pattern more uneven?

Data Source and Transformations

We used the CMIP6 dataset from the assignment, specifically the NCAR CESM2 historical run from the Google Cloud CMIP6 Zarr catalog. The variable is tos, which is monthly sea surface temperature from the Omon table. The original data is too big to load directly on a GitHub Pages site, so we used a Python script with xarray to pull out four equatorial Pacific grid points and save a smaller CSV for D3.

We used anomalies instead of raw temperature because raw ocean temperature would mostly show the seasonal cycle. For each point, we subtract that point's 1981-2010 average for the same calendar month. Then we classify each month using Niño 3.4: at or above +0.5°C is El Niño-like, at or below -0.5°C is La Niña-like, and anything in between is neutral. The page shows 1996-2014 because that is the part of the historical run we exported.

Design Rationale

We mainly use vertical position because we are comparing how big the anomalies are. The top line chart gives the big-picture timeline, while the longitude profile below it shows the west-to-east pattern for the selected month. We used a longitude profile instead of a map because we only sampled four points, so a map would make the data look more detailed than it really is. The summary cards are there so people do not have to calculate the Niño 3.4 value, east-west difference, or warmest region by hand every time the slider moves. The heatmap gives a quick way to see whether a selected month is a one-month spike or part of a longer warm or cool stretch.

Color uses a red-white-blue scale centered at 0°C. Red means warmer than usual, blue means cooler than usual, and white is close to normal. We kept the same color idea across the charts so people do not have to relearn the meaning of color in each panel.

Interaction Design

The phase filter keeps the slider focused on the months that match the selected phase. For example, if the user picks El Niño-like months, the slider skips the neutral and La Niña-like months instead of stopping on unrelated dates. Clicking a dot in the time series jumps to that month, and moving the slider marks the same month in the line chart, brush view, and heatmap. The play button is mainly there for scanning through a phase quickly, and the brush helps zoom into a shorter time period. The region checkboxes let users focus on only part of the Pacific without losing the rest of the interaction.

Development Process

We started with a wider set of ideas than what ended up on the final page. Our first pass had several separate exploratory charts, but it felt more like a chart gallery than one focused interactive visualization. After that, we narrowed it to one question about the east-west SST pattern. Matthew handled the CMIP6 preprocessing and the first time series sketches, Thomas worked on filtering and comparison ideas, and Gilad tested map/satellite-style ideas. For the final page, we kept the CMIP6 SST slice because it fit the El Niño question the best.

In total, we spent about 35-45 people-hours. The slowest parts were figuring out the CMIP6 Zarr workflow, shrinking the data enough for a static website, and fixing the interaction logic so the phase filter did not create empty charts. The final D3 work was mostly connecting the controls to every view, then cleaning up the labels, legends, and write-up so someone could understand what we did without reading the Python script.
