Project Write-Up

Design Rationale

Visual Encodings

The primary mark for the line chart is a path, chosen because climate variables are continuous over time and a connected line best preserves the perceptual impression of trend and rate-of-change—properties that a bar or scatter mark would obscure. For the scatter view, circles encode individual observations so that density and outliers become visible without implying a temporal ordering that may not exist in a cross-sectional slice.

Color is mapped through a diverging (cool–warm) scale for temperature data, anchored at the pre-industrial baseline. Diverging scales are expressively appropriate here because the data is bipolar (anomalies can be positive or negative), and a sequential scale would falsely suggest that every value above zero is "more" of the same thing rather than a departure from a neutral midpoint. For precipitation and CO₂—both ratio-scale variables with a meaningful zero—a sequential, perceptually-uniform scale (viridis) is used instead to avoid implying a neutral midpoint that does not exist in those variables.

Interaction Design

Three interaction idioms were selected to guide users toward patterns that a static plot cannot reveal:

  1. Linked year-range sliders implement a dynamic query pattern: users continuously drag to filter the temporal window and the chart re-renders in under 300 ms, making it easy to isolate multi-decadal trends or short-term anomalies without context-switching.
  2. Variable and region dropdowns provide attribute-based filtering. Changing the variable swaps the y-axis scale and color encoding simultaneously, so users can directly compare the spatial signature of different climate drivers within the same layout.
  3. Tooltip details-on-demand appear on hover and surface exact numeric values along with their metadata (year, region, source model). This avoids cluttering the chart with labels while still letting a user interrogate any single data point precisely—a key principle from the visual information-seeking mantra (Shneiderman, 1996).

Development Process Overview

The project was built in three phases. First, the CSV subset was prepared by filtering the full CMIP6 model output to a manageable number of rows, normalizing column names, and verifying that no sentinel values remained. Second, the visualization skeleton—axes, scales, and static SVG structure—was implemented in js/visualization.js and confirmed with a hard-coded data stub before any real data was wired in. Third, js/main.js was connected to load the CSV asynchronously and dispatch filtered subsets to the chart's update() method whenever a control changed.

The most time-consuming aspect was tuning the D3 enter/update/exit pattern so that transitions remained smooth when the user rapidly moves the year-range sliders. Debouncing the slider input event to 50 ms resolved the visual stuttering caused by firing too many redraws per second.
