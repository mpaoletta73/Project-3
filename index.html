Write-Up

Motivation

Our main question is how Pacific sea surface temperatures shift during El Niño events. We answer it by looking at where the shift shows up along a west-to-east slice of the equatorial Pacific. When Niño 3.4 gets warmer or cooler than normal, does the change show up mostly in the central Pacific, the east, or across the whole sampled slice? This matters because the usual Niño 3.4 index gives one number, but it does not show the rest of the equatorial Pacific changing at the same time.

Data Source and Transformations

We used the CMIP6 dataset from the assignment, specifically the NCAR CESM2 historical run from the Google Cloud CMIP6 Zarr catalog. The variable is tos, which is monthly sea surface temperature from the Omon table. Since the raw Zarr store is too large to load directly in a GitHub Pages site, we used a Python script with xarray to sample four equatorial Pacific grid points and save a smaller CSV for D3.

We did not plot raw temperature because the seasonal cycle would dominate the view. Instead, every value is an SST anomaly: the selected month's SST minus that grid point's 1981-2010 average for the same calendar month. We then classify each month using the Niño 3.4 anomaly. Months at or above +0.5°C are El Niño-like, months at or below -0.5°C are La Niña-like, and the rest are neutral. The page shows 1996-2014 because that is the final part of the historical run we exported.

Design Rationale

The main encoding is position on a shared y-axis because we are comparing anomaly size across time, longitude, and ENSO phase. The top line chart gives the full time context. The longitude profile below it is the main spatial view because the data is a west-to-east slice, not a full map. The summary cards and pattern callout are there so the viewer does not have to mentally calculate the Niño 3.4 value, the east-west gradient, or the warmest region every time they move the slider.

Color uses a red-white-blue diverging scale centered at 0°C. Red means warmer than normal, blue means cooler than normal, and white means close to normal. We tried thinking about a map, but with only four sampled points it made the data look more spatially detailed than it really was. A longitude profile is more honest for this subset because it keeps the east-west ordering without pretending we have a dense field.

Interaction Design

The phase filter works like a dynamic query. If the viewer picks El Niño-like months, the slider only steps through months that actually match that phase, instead of showing blank charts. Clicking points in the line chart jumps to that month, and moving the slider highlights the same month in the time series and brush context. The play button animates through the selected phase, and the brush lets the viewer zoom into a shorter time range. The region checkboxes make it easier to compare only the parts of the Pacific the viewer cares about. We kept all three phase averages visible in the grouped bars, but fade the phases that are not selected, so the comparison does not disappear when filtering.

Development Process

We started wider than this final page. The first pass had several separate exploratory charts, but it felt more like a separate chart gallery than one interactive visualization. After that, we narrowed the final version to one question about the east-west SST pattern. Matthew handled the CMIP6 preprocessing and the first time series sketches, Thomas worked on filtering and comparison ideas, and Gilad tested map/satellite-style ideas. For the final page we kept the CMIP6 SST slice because it was the clearest match to the El Niño question.

In total we spent about 35-45 people-hours. The slowest parts were getting comfortable with the CMIP6 Zarr workflow, reducing the data enough for a static website, and fixing the interaction logic so the phase filter never creates an empty chart. The final D3 work was mostly connecting the controls to all the views, then cleaning up labels, legends, and the write-up so someone could understand the transformations without reading the Python script.
